# Data model

Planned for the back-end phase. Nothing is implemented yet. Draw and review the full ERD before the first migration.

## Naming rules (from CLAUDE.md)

- Table and column names in snake_case, short and descriptive.
- Identifiers end in `_id` and are strings (UUID version 7 generated by the client, stored as text). Describe them as "identifier".
- Foreign keys use the exact name of the referenced key.
- Booleans start with `is_` or `has_`. Dates end in `_date`, timestamps in `_at`, quantities in `_quantity` (never `qty_`).
- A column name shared by several tables has one identical description everywhere.

## Storage rules

- SQLite with `foreign_keys=ON`, `journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout`, set on every connection.
- Money and rates: integers scaled by 10,000 (4 decimals), rounded half away from zero.
- Timestamps UTC. Every table has `created_at` and `updated_at`.
- Names, SKUs and emails compared case-insensitively.
- History is never deleted: products, variants and users use `is_active` or a status; foreign keys restrict deletes.

## Tables

| Area | Table | Key columns |
|---|---|---|
| People | `users` | user_id, full_name, email (unique; required for the owner), user_code (6 digits, unique), password_hash, role_id, app_language, theme, is_active |
| | `roles`, `permissions`, `role_permissions` | Owner, Manager, Cashier |
| Store | `store_settings` (one row) | store name, logo, registration number, address, store language, base and default currency, tax rate (default 0 %), discount cap, inactivity timeout, return window, low-stock default, receipt behaviour, backup schedule, is_pin_enabled |
| Catalogue | `categories`, `brands`, `product_types`, `sizes`, `size_sets`, `colors` | seeded, editable; `is_default`, sort order, colour hex; a product type has an optional size set |
| | `products` | product_id, product_name (generated, editable), model_label, product_type_id, category_id, brand_id, description, is_active, cost and selling price, low_stock_threshold_quantity; unique brand_id + product_type_id + model_label |
| | `product_variants` | variant_id, product_id, size_id, color_id, sku (unique), internal_barcode (unique), supplier_barcode, price overrides, on_hand_quantity (cached), needs_stock_correction |
| | `product_images` | image path, sort order |
| Stock | `stock_adjustments` | adjustment_id, adjustment type, reason, reference, notes, user_id; one type per adjustment |
| | `stock_movements` | movement_id, variant_id, movement_type, change_quantity, after_quantity, adjustment_id, user_id, created_at; append-only |
| Money | `currencies` | USD, EUR, COP, VES; code, symbol, is_active |
| | `payment_methods` | Cash, Card, Transfer, Zelle, USDT, Mobile payment, PayPal, Other, with sort order |
| | `exchange_rates` | currency, rate to base, effective_at, user_id; append-only |
| Sales | `sales` | receipt number, status (completed, voided), totals, discount, tax, user_id, void reason, approver, voided_at; no customer data in the MVP |
| | `sale_items` | variant, quantity, price, cost and tax snapshots |
| | `payments` | sale or return, method, currency, amount, rate, base amount, direction (in, refund) |
| Returns | `returns`, `return_items` | original sale, type (refund, exchange), reason, note, is_no_receipt |
| System | `audit_logs` | audit_log_id, event_type, entity, entity_id, old_value, new_value, user_id, approver_user_id, created_at; append-only. Events: voids, refunds, adjustments, approvals, exports, every settings change, staff and role changes (user added, deactivated, activated, role changed, code regenerated) |
| | `notifications` | type, variant or source, message, is_read |

Movement types: opening_balance, stock_received, sale, customer_return, adjustment, void_reversal. Adjustment types: recount, sold_without_stock, damaged, lost.

On-hand quantity may go negative (sales are never blocked); a negative or oversold variant is flagged `needs_stock_correction` until an adjustment resolves it.
